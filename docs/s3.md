# Amazon S3

Amazon S3 can act as both a source and a destination in an ETL pipeline. It is an object store, not a database, so it works differently from the SQL connectors:

- **As a source** it *lists* objects under a prefix. Each object becomes one record describing the object (bucket, key, size, last modified). **The object's contents are not read.**
- **As a destination** it *writes objects*: every payload you return is one object, uploaded with a single `PutObject`.

It works with Amazon S3 and with S3-compatible services such as MinIO.

## Connection Configuration

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| Region | Text | Yes | AWS region of the buckets, for example `us-east-1` or `ap-south-1` |
| Credentials | Select | Yes | **Access Key** or **Instance Role (EC2 / ECS)** |
| Access Key ID | Text | With Access Key | AWS access key ID |
| Secret Access Key | Password | With Access Key | Secret for that access key |
| Role ARN | Text | No | A role to assume on top of the credentials above, for example `arn:aws:iam::123456789012:role/etl-access` |
| Endpoint | Text | No | Base URL of an S3-compatible service such as MinIO. Setting it switches to **path-style addressing** |

**Authentication.** Choose **Access Key** and enter a key pair, or choose **Instance Role** to resolve credentials from the AWS default chain (environment, shared profile, instance or task role). Role ARN is optional and is assumed on top of whichever credentials were resolved.

:::info Where instance roles resolve
With Instance Role, the credentials come from the machine where the job runs, which is the [runner](runner.md) host, not the ETLFunnel server.
:::

### Required permissions

| Used as | IAM permission |
|---|---|
| Source | `s3:ListBucket` on the bucket |
| Destination | `s3:PutObject` on the keys you write |

## Source Operations

### Data Extraction Methods

```go
type IClientDBS3Source interface {
    GeneratePrefixScan(param *models.S3SourcePrefixScan) (*models.S3SourcePrefixOptions, error)
    FetchRecords(param *models.S3SourceFetch) <-chan *models.Record
}
```

- **Prefix Scan** — lists the objects under a bucket prefix. Select the **By Prefix** data processing strategy
- **Record Fetching** (**By Custom Function**) — full control: stream records yourself through a channel, given the raw `*s3.Client` (AWS SDK for Go v2). Use this to read object contents

### Source Configuration Structure

```go
type S3SourcePrefixScan struct {
    State              IPipelineRuntimeState
    AuxiliaryDBConnMap map[string]IDatabaseConnInfo
}

type S3SourcePrefixOptions struct {
    Bucket  string // required
    Prefix  string // only keys beginning with this are listed; empty lists the whole bucket
    MaxKeys int32  // page size of the listing; 0 uses the service default
}

type S3SourceFetch struct {
    State              IPipelineRuntimeState
    SourceDBConn       *s3.Client
    AuxiliaryDBConnMap map[string]IDatabaseConnInfo
}
```

:::note `MaxKeys` is a page size, not a limit
`MaxKeys` only sets how many objects each listing request returns. **Every object under the prefix is still returned**, across as many pages as needed.
:::

### Example Source

```go
func (c *IUseConnector) GeneratePrefixScan(param *models.S3SourcePrefixScan) (*models.S3SourcePrefixOptions, error) {
    return &models.S3SourcePrefixOptions{
        Bucket: "my-data-lake",
        Prefix: "logs/2026/",
    }, nil
}
```

### Record Shape

One record per object, with these fields:

| Field | Type | Description |
|---|---|---|
| `bucket` | string | Bucket name |
| `key` | string | Full object key |
| `size` | integer | Size in bytes |
| `last_modified` | string | UTC timestamp, for example `"2026-01-02T03:04:05Z"` |

Matching is by plain string prefix, so `logs/2026` also matches `logs/2026-archive/...`. Add a trailing slash (`logs/2026/`) to match only that folder.

### Reading Object Contents

The prefix scan gives you the *list* of objects. To read what is inside them, use `FetchRecords` with the `*s3.Client` it provides.

## Destination Operations

### Data Loading Capabilities

```go
type IClientDBS3Dest interface {
    GenerateQuery(param *models.S3DestQuery) ([]*models.S3DestQueryPayload, error)
    GenerateOptions(param *models.S3DestQuery) (*models.S3DestOptions, error)
}
```

- **Query Generation** — receives a batch of records and returns the objects to write
- **Options Generation** — `S3DestOptions` carries no fields, so `GenerateOptions` is not needed

### Destination Configuration Structure

```go
type S3DestQuery struct {
    State              IPipelineRuntimeState
    Records            []*models.Record
    AuxiliaryDBConnMap map[string]IDatabaseConnInfo
}

type S3DestQueryPayload struct {
    Bucket string // must already exist
    Key    string // an existing object with this key is overwritten
    Body   []byte // empty or nil writes an empty object
}

type S3DestOptions struct{}
```

:::warning Uploads are not transactional
Payloads are uploaded **in order, and each upload commits on its own**. If one fails, the objects before it stay written and the ones after it are not attempted. Use deterministic keys (for example a batch number or a hash of the content) so a retry overwrites the same objects instead of duplicating them.
:::

### Example Destination

This writes each batch as one JSON Lines object:

```go
func (c *IUseConnector) GenerateQuery(param *models.S3DestQuery) ([]*models.S3DestQueryPayload, error) {
    var buf bytes.Buffer
    enc := json.NewEncoder(&buf)
    for _, rec := range param.Records {
        if err := enc.Encode(rec.Data); err != nil {
            return nil, err
        }
    }

    key := fmt.Sprintf("exports/%s/%d.jsonl", param.State.GetName(), time.Now().UnixNano())
    return []*models.S3DestQueryPayload{
        {Bucket: "my-data-lake", Key: key, Body: buf.Bytes()},
    }, nil
}
```

## Connection Casting

An S3 connection reached through `AuxiliaryHub` can be cast to its AWS SDK client from a transformer or other hook:

```go
// Cast IDatabaseConnInfo to an S3 connection
s3Conn, err := CastAsS3Connection(engine)
if err != nil {
    return fmt.Errorf("failed to cast to S3 connection: %v", err)
}

// s3Conn is of type models.DBConnector[*s3.Client] — unwrap the SDK client via .Client
out, err := s3Conn.Client.GetObject(ctx, &s3.GetObjectInput{Bucket: &bucket, Key: &key})
```

The casting function type-asserts the engine against the `IS3Connector` capability interface (`GetS3Client()`) and fails if the engine isn't connected yet.

## Errors and Observability

S3 failures are logged with dedicated [EF codes](ef-codes.md):

| Code | Category |
|------|----------|
| `EF-E655` | Source: dispatch/config error (unknown capture method, or your `GeneratePrefixScan` hook returned an error) |
| `EF-E656` | Source: list/read error. A bucket that can't be listed (missing, or no `s3:ListBucket`) ends the run as a failure at the source stage |
| `EF-E716` | Destination: upload error (the `bucket` and `key` that failed are logged) |

A connection-level failure (network drop, DNS failure, timeout, EOF) is additionally classified as a connection error, which triggers the `EF-E301`–`EF-E306` connection handling rather than a plain read/write error.
